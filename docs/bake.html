Bake a bird

A skeletal mesh and its clips in, a static mesh and three textures out. Five steps, one window.

1. The material

Assign your bird a material you are willing to modify, and set:

SettingValueWhy
Use Material Attributesonmandatory. The bone animation function takes attributes in and returns World Position Offset and Normal on one wire; without this there is no pin to connect
Num Customized UVs1the lookup UVs the bake writes
Used with Instanced Static Meshesonrequired to render on an ISM
Used with Skeletal Meshesononly if you also want the material on the source skeletal mesh
Blend ModeOpaqueMasked costs a great deal more with no depth prepass
Tangent Space Normalon (default)the function's normal path assumes it

Then put MF_FlockBoneAnimation between MakeMaterialAttributes and the MaterialAttributes output.

MF_FlockBoneAnimation is a drop-in for the Anim to Texture plugin's MF_BoneAnimation. Same inputs, same parameters, one extra: an Interpolate static switch, off by default and free while it is off. See Frame interpolation.

Make a material instance from it. That instance is what goes on the baked static mesh, and what the bake pushes frame counts onto.

2. The species asset

Content Browser → Miscellaneous → Data Asset → Flock Species Data, named DA_Species_<Name>.

Leave it empty. The bake fills it in, and the bake recipe lives on it, so it needs to exist before the window has anywhere to write.

3. Bake

Flock → Bake Animation Textures...

  1. Set Species to the asset you just made.
  2. Set Source Skeletal Mesh, Output Path, Asset Name, your Clips and Sample Rate.
  3. Prepare Asset Set, which creates the mesh, the textures and the data asset.
  4. Put your material instance in Bone Material Instances, and on the new static mesh's material slot.
  5. Leave Build Pose Match Table on.
  6. Bake.
Sample Rate must be your animations' actual frame rate. It is a time step, not a frame count: get it wrong and the bake walks off the end of every clip.

What Prepare Asset Set makes

AssetName
Static meshSM_<Name>_VAT
TexturesTX_<Name>_BonePosition, _BoneRotation, _BoneWeight
Data assetDA_<Name>_BoneAnimation

It also sets UVChannel = 1, NumDriverTriangles = 1, moves the lightmap to UV2, and sets bAutoPlay = false. That lightmap move is the most common first-run failure fixed for you: a freshly converted mesh defaults to lightmap 1, and so does UVChannel.

The recipe lives on the species

Not on the window. Assigning a Species loads its recipe; a successful Prepare or Bake writes it back and points the species at what was produced. Moving to another bird costs nothing.

Button
Loadpull the species' recipe into the window, discarding what is there
Save To Speciespush the window's recipe onto the species without baking
Prepare Asset Setcreate the assets, then save the recipe
Bakebake, then save the recipe

Turn off Write Back To Species to use the window as a scratchpad. An empty recipe is never loaded over a populated window, so pointing at a fresh species starts from what you already have.

4. Map the clips

On the species, set Mesh to SM_<Name>_VAT and Anim Data to DA_<Name>_BoneAnimation, then fill Clips. Idle is the only one required. Turn Random Start Phase on for it.

Read the indices off Animations on the data asset, never off the order you typed the clips in.

Indices follow the enabled sequences in data-asset order, and adding animations reorders that list (a multi-select drop sorts alphabetically). Re-check every mapping after any re-bake. The failure is silent: birds animate, with the wrong clips. flock.Debug.Perception 1 names the clip on each bird, which is how you catch it without opening the asset.

The full clip list, what each is for and which are optional, is on Species.

Re-baking

Every re-bake needs the material instance in Bone Material Instances, not just the first one. The instance carries its own copy of NumFrames, and a bake that does not update it leaves the material addressing the old texture: everything past the old frame count clamps to the last row and freezes. Since new clips are appended at the end, this hits exactly the clips you just added and nothing else.

The recipe owns the sequence list. Prepare replaces the data asset's AnimSequences with the recipe's, so a sequence added to the data asset directly survives only until the next Prepare. It refuses rather than dropping one, naming what it found, because losing a sequence moves every animation index after it.

Set bAutoPlay on the data asset, never on the material instance. The bake pushes it onto the AutoPlay switch, so a manual override is silently undone.

Reading the results

FieldExpect
NumFramesthe sum of every enabled clip's frame count
NumBonesyour skeleton's raw bone count, virtual bones excluded
BoneRowsPerFrame1, unless the skeleton is wider than MaxWidth
Animationsone entry per enabled clip, contiguous StartFrame/EndFrame

Texture sizes follow: position and rotation are NumBones × NumFrames + 1, the extra row being the reference pose; the weight texture is the welded vertex count wide by two rows.

Settings worth knowing

SettingDefault
ModeBoneper-bone position and rotation plus a static weight texture. Small, and the textures are shareable between meshes on the same skeleton. Discards bone scale
Vertexper-vertex position and normal. Textures grow with vertex count; keeps scale. Needs MF_VertexAnimation instead
Precision16 bits8 bits quantises position to 256 steps across the whole animation bounds, which stair-steps in slow motion, and caps you at 256 bones
Lightmap Index2must differ from the data asset's UVChannel
Save After Bakeonthe bake only marks packages dirty. Off means your changes revert on restart
Allow Writing Outside Projectoffthe default material instance slots point at the Anim to Texture plugin's Mannequin instances, in engine content with no source control. Only tick this to deliberately re-bake those
Morph targets are not baked in either mode, and there is no root motion extraction: move the instance transform yourself.

5. Look at it

Flock → Spawn Preview in Current Level, or place a Flock VAT Preview actor and set Anim Data. It ticks in the viewport, no PIE.

PropertyDefault
Animation Index0which clip, indexing the data asset's Animations
Loop, Play Rateon, 1
Interpolateoffblends the two frames either side, the way a bird with Interpolate Frames does. Needs a material that reads the third custom data float
Material Overridenonefor A/B-ing one material against another without editing either
Random Phaseonstagger instances, so a grid does not move in unison
Hold Frame-1freeze on one frame instead of playing. Negative plays
Hold Frame Is Absoluteoffaddress the raw baked frame, ignoring the clip range. The tool for telling a bad bake from a bad frame mapping
Count X / Y, Spacing5, 5, 150grid size, for eyeballing instancing cost
Dragging the Frame scalar on the material instance is the cheaper check. If the mesh deforms, the textures, the material and the bake are all right, and whatever is wrong is in the species mapping.

Check both feature levels before trusting a bake. The vertex shader budget is tighter on ES3.1 than SM5.

Watching it go wrong

Watch the Output Log on LogAnimToTextureEditor during a bake. The plugin's own message log listing is never written to, so a failure there is silent everywhere else.

Right-click the species and Validate Data reports a stale pose match table, a mesh that will not load, and a material instance whose frame count disagrees with the bake.

Bakes are traced (FFlockBake::PrepareAssets, ::Bake, ::AnimationToTexture), which is useful when a dense mesh takes a while and you want to know which step.
