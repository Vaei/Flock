Cost

Bird count barely moves the CPU. Triangles and overdraw move the GPU, and the vertex shader is where the real money goes.

In order

  1. Rendering. One ISM primitive per flock, two calls per component per frame. Bird count barely moves the CPU; triangles and overdraw move the GPU. Keep the mesh lean and the material Opaque.
  2. The vertex shader. Bone influences and frame interpolation, paid per vertex in the base pass and again in every shadow depth pass. This does not fall off with distance.
  3. Separation. O(n²) within a chunk, and the only thing here that is not flat in flock size. Separation Max Tier decides how far out it runs (default Near): the further out, the more it costs and the less anyone can see it.
  4. Everything else is flat or tag-gated. Steering never queries neighbours. Threat cost is bounded at four sources per flock regardless of how many exist in the world, and a calm flock's chunks are skipped whole. Culled birds are not visited.

Anim and Render reading non-zero is the proof a flock is live. Nothing in engine core ticks Mass: the only runtime class hosting a processing phase manager ships in the MassGameplay plugin, which this does not require, so Flock runs its own pipeline from the subsystem tick. Those two at zero while birds are placed means the processors are not executing - which looks identical to a query matching nothing.

LOD

Tier comes from camera distance and an estimated screen size, re-evaluated at LOD Rate Hz. Promotion happens at the distance, demotion at LOD Hysteresis past it, with a minimum LOD Dwell Time in a tier, so nothing flickers across a boundary.

TierDistanceRuns
Near2000everything, every frame

LOD Rate Hz4. A tier change moves an archetype, so this is not per frame

Skipped time is folded into a scaled delta, so a Far bird still moves at the right speed. The phase comes from each bird's seed, so work is spread across frames rather than every Far bird spiking on the same one. Tiers are tags, so a Culled bird's chunks are never visited at all rather than visited and skipped.

Idle behaviours run at every tier except Culled, at that tier's stride. Far is included on purpose: a bird part way through a dawdle has to finish it wherever it is.

Networking

Nothing runs on a dedicated server. Birds are cosmetic and simulate independently on each client; nothing is replicated, and two clients will not see the same bird in the same place.

Three separate gates, so no single mistake can put them on a server:

  • Every processor declares Standalone | Client, and Mass reports Server for a dedicated server, so the pipeline is built with zero processors and the subsystem's tick returns immediately.
  • UFlockSubsystem is not created there at all, so there is no audio pool, no actor-spawned handler and no event queue to fill. ScareFlock and the notify find no subsystem and do nothing.
  • AFlockVolume spawns nothing: no entities, no render actor, no instanced meshes.

A listen server is a client too, so it gets birds like any other.
