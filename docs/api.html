In your own code

Scaring them, reacting to a clip, spawning without a volume, driving playback yourself, and scripting the bake.

Scaring them

#include "System/FlockStatics.h"

UFlockStatics::ScareFlock(this, GetActorLocation(), /*Radius*/ 2000.f);
UFlockStatics::ScareFlockAtActor(Actor, /*Radius*/ 2000.f);

Both BlueprintCallable. Nothing to register, nothing to clean up. Full parameters on Being noticed.

Prefer the Scare Flock notify where the moment belongs to an animation.

Making something alarming

A Flock Disturbance Component covers most cases. For a type your own module owns, implement the interface instead:

class AMyBoulder : public AActor, public IFlockDisturbanceInterface
{
    virtual float GetFlockThreatWeight() const override { return 6.f; }
    virtual float GetFlockThreatRadius() const override { return 2500.f; }
    virtual bool  IsFlockThreatActive() const override { return bRolling; }
};

Weight and radius are read once at registration. Only IsFlockThreatActive is polled, and only for actors that implement it, which is what makes unnoticed while crouched free.

Reacting to a clip

UFlockSubsystem::Get(this)->OnClipStarted.AddDynamic(this, &AMyActor::HandleFlockClip);

FlockIndex, Clip, Position. BlueprintAssignable, fired on the game thread the moment the clip starts, for every rest break whether or not it has a sound attached.

Unlike the audio it is never delayed: a clip starting is a clip starting, and Sound Delay does not apply to it. Takeoff and landing have their own audio slots on the species and do not come through here.

Params.Species = MySpecies;

Params.Origin = GetActorLocation();

const int32 FlockIndex = UFlockSubsystem::Get(this)->CreateFlock(Params);
...
UFlockSubsystem::Get(this)->DestroyFlock(FlockIndex);

The same fields the volume exposes: OrbitPreference, bSnapToGround, GroundTraceChannel, MinSpawnSpacing, GroundOffset, MinGroundNormalZ, HeadroomRadius. A volume is a thin wrapper over this.

On a volume, SpawnFlock() and DespawnFlock() are BlueprintCallable; turn off Spawn On Begin Play to drive it yourself.

Driving playback yourself

NumCustomDataFloats = 3 on the ISM.

Float
[0]Frame. Fractional when interpolating, whole otherwise
[1]PrevFrame, written the same as [0]
[2]NextFrame, the whole frame after. Only read when the material's Interpolate switch is on
 
const FAnimToTextureAnimInfo& Range = AnimData->Animations[ClipIndex];
const float NumClipFrames = Range.EndFrame - Range.StartFrame + 1;
const float Elapsed = (Now - ClipStartTime) * PlayRate * AnimData->SampleRate;
const float Local = bLoop ? FMath::Fmod(Elapsed, NumClipFrames)
                          : FMath::Min(Elapsed, NumClipFrames - 1.f);   // one-shots hold on the last frame
const float Frame = Range.StartFrame + Local;
Do not offset Frame to account for the reference pose. Fmod already keeps Local inside [0, NumClipFrames), so adding one makes the last step of every loop sample the next clip's first frame - one wrong frame per cycle, which reads as a flicker. Verify with Hold Frame Is Absolute on the preview actor: the last frame of a clip must still look like that clip. 
Instances->SetCustomData(0, Count - 1, CustomData, /*bMarkRenderStateDirty*/ false);
Leave bMarkRenderStateDirty false when updating every frame. SetCustomData already calls CustomDataChanged per instance, which is the incremental GPU update; marking dirty on top destroys and recreates the scene proxy every frame - wasteful, and visible as flicker.

Frame is a float but the textures are TF_Nearest, so values snap unless the material interpolates. AFlockVATPreview (Flock/Public/Debug/FlockVATPreview.h) is the whole thing working in about sixty lines.

Scripting the bake

The window is a front end for these. For batching several birds, or baking in CI.

import unreal

BIRD = "/Game/Path/To/YourBird"
CLIPS = ["Idle", "TurnLeft", "TakeOff", "Fly", "Land"]

unreal.FlockBakeLibrary.configure_flock_bake(
    f"{BIRD}/SKM_YourBird.SKM_YourBird",   # source skeletal mesh
    f"{BIRD}/VAT",                          # output path
    "YourBird",                             # asset name
    [f"{BIRD}/{c}.{c}" for c in CLIPS],     # clips, in index order
    30.0)                                   # sample rate
unreal.FlockBakeLibrary.set_flock_bake_material_instances(
    [f"{BIRD}/VAT/MI_YourBird_VAT.MI_YourBird_VAT"])

unreal.FlockBakeLibrary.prepare_flock_assets()
unreal.FlockBakeLibrary.bake_flock_textures()

Both return a bool and log failures to LogFlockEditor.

Headless runs need -AllowCommandletRendering, or the mesh conversion returns null and logs nothing. 
UnrealEditor-Cmd.exe <uproject> -run=pythonscript -script="bake.py" ^
    -unattended -nosplash -nosound -AllowCommandletRendering

Instrumenting

FLOCK_SCOPE(Name) from FlockStats.h emits both the stat flock cycle counter and the Insights scope, so the two cannot drift apart. The name matches the STAT_Flock_<Name> id.

void UFlockThreatProcessor::Execute(FMassEntityManager& EntityManager, FMassExecutionContext& Context)
{
    FLOCK_SCOPE(Threat);
    ...
}
Nothing user-facing is spawned from a processor. A Mass processor is not guaranteed to be on the game thread, and spawning an actor, touching a component or broadcasting a delegate from a worker crashes; events go into a locked queue drained once per frame on the game thread instead.
A FMassRuntimePipeline held without UPROPERTY crashes in DebugSetProcessor on tick. Its Processors array is reflected, but only if the struct instance is itself reachable.
